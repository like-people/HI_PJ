# moim — 모임 회비·지출 정산 도구

모임의 지출을 기록하고, 월별·기간 보고서와 정산, 예산·회비를 명령행에서 확인하는 도구입니다.

## 설치와 실행
- Python 3.12 에서 확인했습니다(CI 와 같은 버전). 표준 라이브러리만 쓰므로 따로 설치할 것은 없습니다.
- 설정 파일은 `python -m moim init` 으로 기본값을 만들거나, `config.example.json` 을 `config.json` 으로 복사해서 만듭니다. 만든 뒤 모임 이름, 자료 파일 경로(`data`), 예산·회비 등을 고칩니다. 항목 이름은 `docs/규격합의_기능별.md` 8절에 있습니다.
- 설정 파일은 기본으로 현재 폴더의 `config.json` 을 읽습니다. 다른 파일은 `--config` 로 지정합니다(`init` 도 같습니다).

```
python -m moim --help                      # 명령 묶음 목록
python -m moim report --help               # 묶음마다 하위 명령 목록
python -m moim --config 다른설정.json report period --month 2026-11
```

### 설정 파일 만들기: `init`
`init` 은 기본 설정 파일을 만듭니다. 파일 이름은 `--config` 로 정하고(`init` 앞에 씁니다) 주지 않으면 `config.json` 입니다. 이미 있는 파일은 덮어쓰지 않고 오류를 냅니다. 설정 파일만 만들며, 자료 파일은 처음 저장할 때 만들어집니다. 기본값에는 모임 이름 `우리 모임`, 경고 비율 0.8 이 들어 있고 예산·회비는 비어 있습니다. 아래 절의 예산·회비 예는 이 항목들을 고친 설정으로 실행한 것입니다.

```
python -m moim init
python -m moim --config 다른설정.json init
```
```
설정 파일을 만들었습니다: config.json
설정 파일을 만들었습니다: 다른설정.json
```

처음 만들어지는 `config.json` 은 다음과 같습니다.

```
{
  "group": "우리 모임",
  "data": "data.json",
  "members_file": "members.txt",
  "rules": "rules.json",
  "backup_dir": "backup",
  "log_dir": "logs",
  "treasurer": null,
  "budget": {
    "monthly": null,
    "by_category": {}
  },
  "dues": {
    "monthly": null
  },
  "warn_ratio": 0.8
}
```

같은 이름의 파일이 이미 있거나 파일을 만들 폴더가 없으면 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다.

```
python -m moim init
python -m moim --config 없는폴더/설정.json init
```
```
오류: 이미 있습니다: config.json
오류: 설정 파일을 만들 폴더가 없습니다: 없는폴더
```

## 명령 묶음
| 묶음 | 하는 일 |
|---|---|
| `member` | 참여자 명부 |
| `exp` | 지출 입력·관리 |
| `cat` | 분류 규칙 |
| `report` | 월별·기간 보고서 |
| `settle` | 정산 |
| `budget` | 예산·회비 |
| `io` | 가져오기·내보내기 |

명령마다 사용 예와 출력 예는 아래에 모아 둡니다. 이 문서는 명령이 병합될 때마다 늘려 갑니다.

## 참여자 명부 (`member`)
모임 참여자와 가입일·탈퇴일을 관리합니다. 다른 명령은 이 명부를 보고 누가 그날 활동 중인 회원인지 판단합니다(탈퇴일 당일까지는 회원입니다). 하위 명령은 `load`(파일에서 읽기), `add`(추가), `leave`(탈퇴), `list`(목록)입니다.

### 명부 파일 읽기: `member load`
명부 파일은 한 줄에 한 사람이며 `이름,가입일[,탈퇴일]` 형식(날짜는 `YYYY-MM-DD`)입니다. `--file` 로 파일을 정하고, 주지 않으면 설정의 `members_file` 을 읽습니다. 새 이름은 추가하고, 탈퇴일이 적힌 사람은 탈퇴로 반영합니다. 같은 파일을 다시 읽어도 바뀌지 않습니다. 아래 예는 빈 명부에서 시작해, 다음 내용의 `명부.txt` 를 읽습니다.

```
김민수,2026-09-01
이서연,2026-09-01
박지훈,2026-09-01
```

```
python -m moim member load --file 명부.txt
python -m moim member list
python -m moim member load --file 명부.txt
```
```
추가 3명, 탈퇴 반영 0명, 오류 0줄
이름    가입일      탈퇴일
--------------------------
김민수  2026-09-01  -
이서연  2026-09-01  -
박지훈  2026-09-01  -
추가 0명, 탈퇴 반영 0명, 오류 0줄
```

형식이 잘못된 줄은 건너뛰고 몇 번째 줄인지 알려 줍니다(`잘못된명부.txt` 에는 `이름만` 한 줄만 있습니다).

```
python -m moim member load --file 잘못된명부.txt
```
```
추가 0명, 탈퇴 반영 0명, 오류 1줄
1번째 줄: 형식이 잘못되었습니다(이름,가입일[,탈퇴일])
```

### 추가, 탈퇴, 목록: `member add`, `member leave`, `member list`
`member add 이름 --joined 가입일` 은 회원을 하나 추가하고, `member leave 이름 --date 탈퇴일` 은 탈퇴를 기록합니다. `member list` 는 명부 순서대로 이름, 가입일, 탈퇴일(없으면 `-`)을 보여 줍니다. 명부가 비어 있으면 `명부에 회원이 없습니다.` 를 보여 줍니다. `add` 와 `leave` 는 자료를 바꿉니다.

```
python -m moim member add 정하윤 --joined 2026-11-25
python -m moim member leave 정하윤 --date 2026-11-25
python -m moim member list
```
```
회원을 추가했습니다: 정하윤 (가입일 2026-11-25)
탈퇴를 기록했습니다: 정하윤 (탈퇴일 2026-11-25)
이름    가입일      탈퇴일
------------------------------
김민수  2026-09-01  -
이서연  2026-09-01  -
박지훈  2026-09-01  -
정하윤  2026-11-25  2026-11-25
```

### 오류가 나는 경우
이미 있는 이름, 없는 날짜, 명부에 없는 회원, 가입일보다 빠른 탈퇴일은 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다. 자료는 바뀌지 않습니다.

```
python -m moim member add 김민수 --joined 2026-10-01
python -m moim member add 최도윤 --joined 2026-13-01
python -m moim member leave 없는사람 --date 2026-11-30
python -m moim member leave 정하윤 --date 2026-11-01
```
```
오류: 이미 명부에 있는 이름입니다: 김민수
오류: 날짜가 잘못되었습니다(YYYY-MM-DD, 실제 있는 날짜): 2026-13-01
오류: 명부에 없는 회원입니다: 없는사람
오류: 탈퇴일이 가입일(2026-11-25)보다 빠릅니다: 2026-11-01
```

## 지출 입력·관리 (`exp`)
지출을 기록하고 고치고 지웁니다. 지출은 번호가 붙어 쌓이고, 다른 명령(`report`, `settle`, `cat`, `budget`)은 이 지출을 읽어 계산합니다. 아래 예는 모임 참여자 김민수·이서연·박지훈이 있는 상태에서 보고서 절의 지출 4건을 기록하는 것으로 시작합니다.

### 지출 추가와 목록: `exp add`, `exp list`
`--date`(지출일), `--payer`(낸 사람), `--amount`(금액), `--members`(참여자, `;` 로 구분)는 꼭 주고, `--memo`(메모), `--category`(분류), `--weights`(분담 비율)는 선택입니다. 분담 비율을 주지 않으면 참여자가 똑같이 나눕니다. `exp list` 는 번호순으로 보여 주고 `--order date` 를 주면 날짜순으로 보여 줍니다. 분류를 정하지 않은 지출은 `미분류` 로 나옵니다.

```
python -m moim exp add --date 2026-10-05 --payer 김민수 --amount 3000 --members "김민수;이서연;박지훈" --memo "10월 점심" --category 식비
python -m moim exp add --date 2026-11-12 --payer 이서연 --amount 6000 --members "김민수;이서연;박지훈" --memo "점심 식대" --category 식비
python -m moim exp add --date 2026-11-13 --payer 김민수 --amount 9000 --members "김민수;이서연;박지훈" --memo 택시 --category 교통
python -m moim exp add --date 2026-11-20 --payer 박지훈 --amount 2400 --members "김민수;이서연;박지훈"
python -m moim exp list
```

### 수정과 삭제: `exp edit`, `exp delete`
`exp edit 번호` 에 고치고 싶은 항목만 주면 그것만 바뀝니다. `--equal` 은 분담 비율을 없애고 똑같이 나눕니다(`--weights` 와는 함께 쓸 수 없습니다). 삭제한 지출은 목록과 보고서, 정산에서 빠집니다. 정산이 확정된 기간의 날짜는 추가·수정·삭제할 수 없습니다(`settle lock` 참고).

```
python -m moim exp add --date 2026-11-21 --payer 김민수 --amount 1000 --members "김민수;이서연;박지훈" --memo 간식 --weights "김민수=2;이서연=1;박지훈=1"
python -m moim exp edit 5 --amount 1200 --memo "간식(수정)" --equal
python -m moim exp edit 5 --category 식비
python -m moim exp list --order date
```

### 수정 이력, 되돌리기, 되살리기: `exp history`, `exp undo`, `exp restore`
지출을 추가·수정·삭제할 때마다 이력이 남습니다. `exp history 번호` 는 그 지출의 이력을, 번호를 주지 않으면 모든 지출의 이력을 오래된 것부터 보여 줍니다. 시각은 명령을 실행한 때의 시각이라 직접 실행하면 다르게 나옵니다. `exp undo 번호` 는 그 지출의 가장 최근 수정을 한 단계 되돌립니다(여러 번 하면 한 단계씩 더 거슬러 갑니다). `exp restore 번호` 는 삭제한 지출을 되살립니다. 되돌리기와 되살리기도 이력에 남습니다. 아래 예는 위에서 삭제한 5번 지출로 시작합니다.

```
python -m moim exp history 5
python -m moim exp restore 5
python -m moim exp undo 5
python -m moim exp history 5
python -m moim exp delete 5
```

### 파일로 한꺼번에 입력: `exp import-lines`
파일 한 줄이 지출 하나이며 `날짜,낸 사람,금액,참여자1;참여자2,메모` 형식입니다. 메모는 생략할 수 있고, 메모에 쉼표가 있으면 큰따옴표로 감쌉니다. 빈 줄과 `#` 로 시작하는 줄은 건너뜁니다. 잘못된 줄은 몇 번째 줄인지 알려 주고 건너뛰며, 나머지는 입력합니다. 결과는 `추가 N건, 오류 N줄` 로 알려 줍니다. 아래 예는 다음 내용의 `지출목록.txt` 를 읽습니다.

```
# 날짜,낸 사람,금액,참여자,메모
2026-11-22,이서연,4500,김민수;이서연;박지훈,커피
2026-11-23,박지훈,12000,김민수;박지훈,"저녁, 회식"

2026-11-24,김민수,0,김민수;이서연,잘못된 금액
2026-11-25,최도윤,3000,김민수;이서연,없는 회원
2026-11-26,김민수,5000
```

```
python -m moim exp import-lines 지출목록.txt
python -m moim exp list
python -m moim exp delete 6
python -m moim exp delete 7
```
```
추가 2건, 오류 3줄
5번째 줄: 금액은 1원 이상이어야 합니다
6번째 줄: 지출일에 활동 중인 회원이 아닌 낸 사람입니다: 최도윤
7번째 줄: 형식이 잘못되었습니다(날짜,낸 사람,금액,참여자1;참여자2,메모)
번호  날짜        낸 사람  금액(원)  분류    참여자                메모
```

### 되돌리기·되살리기·파일 오류
수정한 적이 없는 지출, 삭제된 지출, 없는 번호, 없는 파일은 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다. 삭제되지 않은 지출을 되살리려 하면 오류가 아니라 안내만 하고 아무것도 바꾸지 않습니다. 정산이 확정된 기간의 날짜는 되돌리기와 되살리기도 할 수 없습니다.

```
python -m moim exp restore 4
python -m moim exp undo 4
python -m moim exp undo 5
python -m moim exp restore 99
python -m moim exp import-lines 없는파일.txt
```
```

오류: 삭제된 지출은 되돌릴 수 없습니다: 5번

오류: 파일을 찾을 수 없습니다: 없는파일.txt
```

### 오류가 나는 경우
없는 번호, 활동 중인 회원이 아닌 낸 사람, 1원보다 작은 금액은 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다. 자료는 바뀌지 않습니다.

```
python -m moim exp delete 99
python -m moim exp add --date 2026-11-21 --payer 최도윤 --amount 1000 --members "김민수;이서연"
python -m moim exp add --date 2026-11-21 --payer 김민수 --amount 0 --members "김민수;이서연"
```
```

오류: 금액은 1원 이상이어야 합니다
```

## 분류 규칙 (`cat`)
지출을 `식비`, `교통` 같은 분류로 나누는 규칙을 관리합니다. 규칙은 설정의 `rules` 파일에 저장되고, 지출의 메모에 키워드가 하나라도 들어 있으면 그 분류로 정하고, 맞는 규칙이 여럿이면 우선순위가 높은 규칙을 따릅니다. 아래 예는 보고서 절의 지출 4건을 그대로 씁니다.

### 규칙 추가와 목록: `cat add-rule`, `cat rules`
분류 이름 뒤에 `--keywords` 로 키워드를 `;` 로 이어서 줍니다. 앞의 번호는 `cat remove-rule 번호` 에 쓰입니다.

```
python -m moim cat rules
python -m moim cat add-rule 식비 --keywords "점심;식대"
python -m moim cat add-rule 교통 --keywords "택시;버스"
python -m moim cat rules
```
```
규칙이 없습니다
규칙을 추가했습니다: 식비
규칙을 추가했습니다: 교통
1. 식비 | 키워드: 점심;식대 | 우선순위 0
2. 교통 | 키워드: 택시;버스 | 우선순위 0
```
`--priority`, `--payer`, `--min-amount`, `--max-amount` 로 우선순위와 조건을 더할 수 있습니다.

### 살펴보기: `cat uncategorized`, `cat summary`, `cat overlaps`
분류가 없는 지출, 분류별 건수와 금액, 같은 키워드가 서로 다른 분류의 규칙에 함께 들어 있는 경우를 보여 줍니다. `summary` 는 `--month` 또는 `--start`, `--end` 로 기간을 줍니다.

```
python -m moim cat uncategorized
python -m moim cat summary --month 2026-11
python -m moim cat overlaps
```
```
4번 2026-11-20 박지훈 2,400원
교통 1건 9,000원
식비 1건 6,000원
미분류 1건 2,400원
겹치는 키워드가 없습니다
```

### 다시 분류와 직접 정하기: `cat apply`, `cat set`, `cat unfix`
`cat apply` 는 모든 지출을 규칙대로 다시 분류하고, `--preview` 를 붙이면 바꾸지 않고 몇 건이 바뀔지만 보여 줍니다. 분류를 직접 정한(`cat set`) 지출과 정산이 확정된 기간의 지출은 `cat apply` 가 바꾸지 않으며, `cat unfix 번호` 로 고정을 풉니다.

위 "살펴보기"의 명령을 먼저 실행한 뒤에 따라 치세요. `cat set` 을 하고 나면 4번 지출에 분류가 생겨서 `cat uncategorized`, `cat summary` 결과가 달라집니다.

```
python -m moim cat apply --preview
python -m moim cat set 4 기타
```
```
0건 바뀔 예정
4번 분류를 기타(으)로 정했습니다
```

없는 지출 번호를 주면 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다.

```
python -m moim cat set 99 기타
```
```
오류: 없는 지출 번호입니다: 99
```

## 예산·회비 (`budget`)
월 예산과 모임 통장(회비 입금 − 지출)을 확인합니다. 월 예산(`budget.monthly`), 분류별 예산(`budget.by_category`), 월 회비(`dues.monthly`), 경고 비율(`warn_ratio`)은 설정 파일에서 읽습니다. 아래 예는 월 예산 15,000원, 분류별 예산 식비 8,000원·교통 100,000원, 월 회비 20,000원, 경고 비율 0.8, 보고서 절의 지출 4건, 회원 김민수·이서연·박지훈 으로 실행한 것입니다.

### 월 예산 상태: `budget status`
`--month YYYY-MM` 으로 달을 주고(없으면 이번 달), `--today YYYY-MM-DD` 를 주면 그날까지의 지출만 셉니다. 상태는 지출이 예산을 넘으면 `초과`, 예산의 경고 비율을 넘으면 `경고`, 월 예산이 설정돼 있지 않으면 `미설정`, 그 밖에는 `정상` 입니다. 지출이 예산의 경고 비율과 딱 같으면 아직 경고가 아닙니다.

```
python -m moim budget status --month 2026-11 --today 2026-11-22
python -m moim budget status --month 2026-11 --today 2026-11-13
python -m moim budget status --month 2026-10 --today 2026-10-31
```
```
2026-11 월 예산 15,000원 | 지출 17,400원 | 남은 금액 -2,400원 | 상태: 초과
2026-11 월 예산 15,000원 | 지출 15,000원 | 남은 금액 0원 | 상태: 경고
2026-10 월 예산 15,000원 | 지출 3,000원 | 남은 금액 12,000원 | 상태: 정상
```

### 분류별 예산 상태: `budget category`
`--month YYYY-MM` 으로 달을 주면(없으면 이번 달) 분류마다 예산, 지출, 남은 금액, 상태를 표로 보여 줍니다. 설정 파일의 분류별 예산(`budget.by_category`)에 적은 분류만 보여 주고, 아무것도 적지 않았으면 `분류별 예산이 설정되어 있지 않습니다` 를 보여 줍니다.

```
python -m moim budget category --month 2026-11
```
```
분류     예산   지출  남은 금액  상태
-------------------------------------
식비    8,000  6,000      2,000  정상
교통  100,000  9,000     91,000  정상
```

### 회비 입금 기록: `budget pay`
회원 이름과 금액을 주고, `--date` 로 입금일(없으면 오늘)을, `--memo` 로 메모를 적습니다. 입금을 기록하면 자료 파일이 바뀝니다.

```
python -m moim budget pay 김민수 20000 --date 2026-11-01 --memo "11월 회비"
python -m moim budget pay 이서연 20000 --date 2026-11-03
```
```
회비 입금을 기록했습니다: 2026-11-01 김민수 20,000원 (11월 회비)
회비 입금을 기록했습니다: 2026-11-03 이서연 20,000원
```

### 모임 통장 잔고: `budget balance`
회비 입금 합계에서 지출 합계를 뺀 금액입니다. `--until YYYY-MM-DD` 를 주면 그날까지만 셉니다. 위의 입금 두 건(40,000원)에서 지출 20,400원을 뺀 값입니다.

```
python -m moim budget balance --until 2026-11-30
```
```
모임 통장 잔고(2026-11-30 기준): 19,600원
```

### 회비 미납자: `budget unpaid`
`--month YYYY-MM` 으로 달을 주면(없으면 이번 달) 그 달 1일이나 말일에 회원인 사람 가운데 월 회비를 다 내지 않은 회원의 이름, 낸 회비, 부족액을 보여 줍니다. 모두 냈으면 `회비 미납자가 없습니다` 를, 월 회비가 설정돼 있지 않으면 `월 회비가 설정되어 있지 않습니다` 를 보여 줍니다. 위에서 입금을 기록한 뒤의 결과입니다.

```
python -m moim budget unpaid --month 2026-11
```
```
이름    낸 회비  부족액
-----------------------
박지훈        0  20,000
```

### 입금 오류
명부에 없는 회원이거나 입금액이 1원보다 작으면 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다. 자료는 바뀌지 않습니다.

```
python -m moim budget pay 최도윤 20000 --date 2026-11-03
python -m moim budget pay 김민수 0 --date 2026-11-03
```
```
오류: 명부에 없는 회원입니다: 최도윤
오류: 회비 입금액은 1원 이상이어야 합니다
```

## 정산 (`settle`)
사람마다 얼마를 냈고 얼마를 부담해야 하는지 보여 줍니다. 아래 예는 보고서 절의 지출 4건(참여자 세 명이 똑같이 나눔)으로 실행한 것입니다. 하위 명령은 `balance`(잔액), `transfer`(송금 기록), `lock`·`locks`(정산 확정)입니다.

### 잔액 확인: `settle balance`
기간을 `--month YYYY-MM` 또는 `--start YYYY-MM-DD --end YYYY-MM-DD` 로 줍니다. 사람마다 기간 안에 낸 돈, 부담할 돈, 이미 보낸 송금과 받은 송금, 잔액을 보여 줍니다.

- 잔액 = 낸 돈 − 부담 + 보낸 송금 − 받은 송금
- 잔액이 양수이면 받을 돈, 음수이면 보낼 돈입니다.
- 마지막 줄의 잔액 합계는 항상 0 이어야 하고, 0 이 아니면 경고를 덧붙입니다.
- `balance` 는 자료를 바꾸지 않습니다.

```
python -m moim settle balance --month 2026-11
python -m moim settle balance --start 2026-10-01 --end 2026-11-30
```
```
이름    낸 돈   부담  보낸 송금  받은 송금    잔액
--------------------------------------------------
김민수  9,000  5,800          0          0   3,200
이서연  6,000  5,800          0          0     200
박지훈  2,400  5,800          0          0  -3,400
잔액 합계: 0
이름     낸 돈   부담  보낸 송금  받은 송금    잔액
---------------------------------------------------
김민수  12,000  6,800          0          0   5,200
이서연   6,000  6,800          0          0    -800
박지훈   2,400  6,800          0          0  -4,400
잔액 합계: 0
```
기간에 지출이 없으면 `정산할 지출이 없습니다` 와 `잔액 합계: 0` 만 나옵니다.

### 송금 기록: `settle transfer`
이미 보낸 돈을 기록합니다(부분 정산). `--date`(송금한 날), `--from`(보낸 사람), `--to`(받은 사람), `--amount`(송금액)를 모두 줍니다. 기록한 송금은 보낸 사람의 `보낸 송금`, 받은 사람의 `받은 송금` 으로 잔액에 반영됩니다. 이 명령은 자료를 바꿉니다. 송금액이 1원보다 작거나 명부에 없는 사람이면 오류입니다.

```
python -m moim settle transfer --date 2026-11-25 --from 박지훈 --to 김민수 --amount 3400
python -m moim settle balance --month 2026-11
```
```
송금을 기록했습니다: 2026-11-25 박지훈 → 김민수 3,400원
이름    낸 돈   부담  보낸 송금  받은 송금  잔액
------------------------------------------------
김민수  9,000  5,800          0      3,400  -200
이서연  6,000  5,800          0          0   200
박지훈  2,400  5,800      3,400          0     0
잔액 합계: 0
```

### 정산 확정: `settle lock`, `settle locks`
기간을 `--month` 또는 `--start`, `--end` 로 주면 그 기간의 정산을 확정합니다. 확정한 기간의 날짜는 지출을 더 이상 추가·수정·삭제할 수 없고, `cat apply` 도 바꾸지 않습니다. 이미 확정한 기간을 다시 확정하면 알려 주기만 합니다. `settle locks` 는 확정한 기간 목록을 보여 줍니다.

```
python -m moim settle lock --month 2026-11
python -m moim settle locks
python -m moim settle lock --month 2026-11
```
```
정산을 확정했습니다: 2026-11-01 ~ 2026-11-30
시작일      끝일
----------------------
2026-11-01  2026-11-30
이미 확정한 기간입니다: 2026-11-01 ~ 2026-11-30
```
확정한 기간의 지출을 고치려 하면 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다.

```
python -m moim exp edit 2 --amount 7000
```
```
오류: 정산이 확정된 날짜의 지출은 수정할 수 없습니다: 2026-11-12
```

### 오류가 나는 경우
기간을 주지 않으면 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다.

```
python -m moim settle balance
```
```
오류: 기간을 지정하십시오(--month YYYY-MM 또는 --start, --end)
```

## 가져오기·내보내기 (`io`)
지출을 파일로 내보내고, 내보낸 파일의 합계가 기록과 같은지 검사합니다. 하위 명령은 `export`(내보내기)와 `verify`(검사)입니다. 두 명령 모두 자료를 바꾸지 않습니다. 아래 예는 위의 예를 모두 따라 한 상태(지출 4건, 4번 지출의 분류는 `기타`)에서 실행한 것입니다.

### 내보내기: `io export`
`io export 파일` 은 지출을 파일로 저장합니다. 파일 이름이 `.json` 으로 끝나면 JSON, 그렇지 않으면 CSV 로 저장하며, 같은 이름의 파일이 있으면 덮어씁니다. 기간(`--month` 또는 `--start`, `--end`)을 주지 않으면 모든 지출을, `--category` 를 주면 그 분류만 내보냅니다. 삭제한 지출은 내보내지 않습니다. 끝나면 건수와 합계를 알려 줍니다.

```
python -m moim io export 지출.csv --month 2026-11
python -m moim io export 전체.json
python -m moim io export 식비.csv --category 식비
```
```
내보냈습니다: 지출.csv (3건, 합계 17,400원)
내보냈습니다: 전체.json (4건, 합계 20,400원)
내보냈습니다: 식비.csv (2건, 합계 9,000원)
```

`지출.csv` 의 내용은 다음과 같습니다. 엑셀에서 한글이 깨지지 않도록 UTF-8(BOM)으로 저장하며, 참여자는 `;` 로 이어 씁니다. `weights` 칸은 분담 비율을 `이름:비율` 로 적은 것이고 똑같이 나누는 지출은 비어 있습니다. JSON 은 `{"expenses": [...]}` 모양이고, 분류가 없거나 똑같이 나누는 항목은 `null` 입니다.

```
id,date,payer,amount,members,weights,category,memo
2,2026-11-12,이서연,6000,김민수;이서연;박지훈,,식비,점심 식대
3,2026-11-13,김민수,9000,김민수;이서연;박지훈,,교통,택시
4,2026-11-20,박지훈,2400,김민수;이서연;박지훈,,기타,
```

### 내보낸 파일 검사: `io verify`
내보낸 파일의 금액 합계가 기록의 합계와 같은지 알려 줍니다. 내보낼 때 준 기간과 분류를 똑같이 주어야 같은 범위끼리 비교합니다.

```
python -m moim io verify 지출.csv --month 2026-11
python -m moim io verify 전체.json
python -m moim io verify 식비.csv --category 식비
python -m moim io verify 지출.csv
```
```
파일 합계 17,400원, 기록 합계 17,400원 → 같습니다
파일 합계 20,400원, 기록 합계 20,400원 → 같습니다
파일 합계 9,000원, 기록 합계 9,000원 → 같습니다
파일 합계 17,400원, 기록 합계 20,400원 → 다릅니다
```

마지막 예는 11월만 내보낸 파일을 기간 없이(전체 기록과) 비교했기 때문에 다르게 나온 것입니다. 이럴 때는 내보낼 때와 같은 기간·분류를 주었는지 먼저 확인하세요.

### 오류가 나는 경우
달 형식이 잘못되었으면 한 줄로 이유를 알려 주고 종료 코드 1 로 끝납니다.

```
python -m moim io verify 지출.csv --month 2026-13
```
```
오류: 달 형식이 잘못되었습니다(YYYY-MM): 2026-13
```
