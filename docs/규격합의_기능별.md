# 공통 모듈 규격 — 기능별로 정할 것 (초안)

11/18 제안발표의 "공통 모듈 함수 규격 합의"(함수 이름, 받는 값, 돌려주는 값의 형식, 담당, 규약 값 예)와
`docs/미정사항.md` 3번을 채우기 위한 초안이다. 각 담당자가 자기 절을 확인하고 고쳐서 "확정"으로 바꾼다.
고친 뒤에는 단톡방에 변경 사항을 알린다.

상태 표시
- **확정**: 스켈레톤 코드·공고문·구현순서 문서로 이미 정해진 것. 바꾸지 않는다
- **확정(이름, 날짜)**: 담당자가 정해서 확정한 것. 누가 언제 확정했는지 적는다. 바꾸려면 그 사람과 먼저 이야기한다
- **제안함, 확인 부탁**: 기능 4(김영광) 담당 항목을 김영광이 제안한 것. 쓰는 기능 담당자가 확인하면 **확정** 으로 바꾼다
- **미정(참고안: 김영광)**: 다른 담당자의 항목. 결정은 그 담당자가 한다. 참고안은 초안 작성자의 의견일 뿐이며, 담당자가 정해서 자기 PR로 **확정** 으로 바꾼다
- **미정**: 담당자가 정해야 하는 것

누가 제안하고 누가 확인하나
- **제안할 사람**: 그 함수·자료 항목·공동 작업의 담당자. 단톡방이나 이 문서를 고치는 PR로 답을 낸다
- **확인할 사람**: 그 결과를 가져다 쓰는 기능의 담당자. 내 코드가 그 형식으로 동작하는지 보고 PR에 검토 의견을 남긴다
- 확인할 사람이 "—"이면 그 기능 안에서만 쓰는 것이라 담당자가 혼자 정한다
- 이름: 기능 1 이승경 · 기능 2 백지윤 · 기능 3 류훈태 · 기능 4 김영광 · 기능 5 이정배 · 기능 6 류강현

## 0. 기본 사항

### 0-1. 채점 때 교수님이 정한 방식

공고문 7쪽: "각자의 기능은 스켈레톤 코드가 정한 규약 함수(금액, 날짜·기간, 회원 판정, 잠금 판정 등)만 교수가 보관한 정상 판으로 바꿔 끼워 실행해 채점한다."

- 해당 함수로 보이는 것: `money.*`(`split` 비율 분배 포함), `dates.*`, `queries.is_member_active`, `queries.is_locked`
- 영향:
  - 이 함수들에 규약에 없는 동작(추가 검사, 다른 반환 형식)을 넣으면 안 된다. 채점 때는 사라진다
  - 이 함수들이 읽는 자료 형식(명부 `members`, 확정 기간 `locks`)이 채점 프로그램의 함수가 읽는 형식과 다르면 채점 때 동작하지 않는다
- **이 함수들은 규약대로만 채우고 다른 동작을 넣지 않는다.** 고쳐야 할 것 같으면 먼저 팀에 묻는다

## 1. 기능 1 — 지출 입력·관리 (이승경)

### 1-1. 공통 함수

| 함수 | 받는 값 | 돌려주는 값 | 쓰는 기능 | 상태 |
|---|---|---|---|---|
| `ledger.validate(store, date, payer, amount, members, weights=None)` | 날짜 문자열/date, 낸 사람 이름, 금액(문자열·숫자), 참여자 이름 목록, 선택적 비율 | 성공 시 `(정규화 날짜, 원 정수 금액)` — 날짜는 `"YYYY-MM-DD"`; 실패 시 이유를 담은 `ValueError` | 6(가져오기 미리 보기) | 이름·인자 확정, 반환·검사 규격 **확정(이승경, 11/16; 김영광 확인; 류강현 확인)** |
| `ledger.insert(store, date, payer, amount, members, memo="", weights=None, category=None, recurring_id=None, action="add")` | 위 + 메모, 분류, 반복 번호, 이력 종류 | 새로 저장한 지출 dict. 확정된 기본 필드 및 전달받은 선택 필드 사용 | 4, 5, 6 | 이름·인자 확정, 반환·기본 저장 규격 **확정(이승경, 11/16)**; 사용 담당 확인 필요 |
| `Store.record(action, eid, before, after)` | 이력 종류 문자열, 지출 번호 정수, 변경 전·후 지출 dict 또는 `None` | `None`(이력 한 건 기록) | 4(`exclude_member`) | 이름·인자 확정, 이력 형식 **확정(이승경, 11/16; 김영광 확인)** |

`validate`의 검사 규격 **확정(이승경, 11/16)**:

- `money.to_won`으로 금액을 정규화하고 1원 이상인지 검사한다. 날짜는 실제 존재하는 날짜여야 하며 `YYYY-MM-DD` 문자열로 정규화한다(`moim/common` 날짜 규약 사용).
- 참여자는 1명 이상이어야 하며, 낸 사람과 참여자 모두 명부에 있고 지출일에 활동 중이어야 한다(`queries.is_member_active`). **낸 사람이 참여자에 포함될 필요는 없다.** 참여자 중복도 거부한다.
- `weights`가 `None`이면 균등 분배로 취급한다. 비율을 지정했다면 키는 `members`의 이름과 정확히 같아야 하고 각 값은 `bool`이 아닌 1 이상의 정수여야 한다. 금액 분배 자체는 `money.split`만 사용한다.
- `queries.is_locked(store, date)`가 참이면 거부한다. 이는 기능 6의 미리 보기에서도 확정 기간을 통과시키지 않기 위한 규칙이다. **김영광 확인 완료; 류강현 확인 완료**
- 실패 시 이유를 담은 `ValueError`를 발생시킨다. **중복 의심은 유효성 검사 실패가 아니다.** 중복 탐지(`ledger.duplicates`)는 호출 측에서 경고 처리한다.

`insert`의 저장 규격 **확정(이승경, 11/16)**:

- `validate`를 통해 검증한 뒤 `Store.new_id`로 번호를 부여하고, `date`, `payer`, `amount`, `members`, `category`, `memo`, `deleted=False`를 저장한다. 제공된 `weights`와 `recurring_id`는 다른 담당자의 확정 형식에 맞춰 저장하며, 지정하지 않은 경우 `None`을 사용한다.
- 이력에는 `Store.record(action, eid, None, 새 지출)`을 호출한다. `action`의 기본값은 `"add"`; 반복 지출처럼 호출자가 다른 이력 종류를 전달하더라도 그 문자열을 보존한다.
- `insert`는 새 항목을 **저장소의 메모리 자료에 추가한 뒤 해당 dict를 반환**하며, 파일 저장은 기존 명령 흐름에서 `Store.save()`로 처리한다. 스켈레톤의 기존 저장 호출 위치가 있다면 중복 저장을 만들지 않는다.
- `category_fixed` 등 타 담당자 관리 필드는 해당 담당자의 확정 규격을 따른다. 기능 1이 타 담당자의 기본값이나 판정 규칙을 임의로 바꾸지 않는다.

수정·삭제·복구 공통 규칙 **확정(이승경, 11/16)**:

- 기존 지출의 날짜가 잠겨 있으면 수정·삭제·되살리기를 거부한다. 수정 후 날짜가 잠긴 기간에 들어가는 것도 거부한다. 수정 결과는 `validate`로 재검증한다.
- `members`가 바뀐 경우 기존 `weights`의 키와 새 참여자가 다르면 자동으로 비율을 재배분하지 않고 `ValueError`로 거부한다. **명시적으로 `weights=None`을 지정해 균등 분배로 변경하는 것은 허용한다.** 스켈레톤의 `edit_expense(store, eid, **changes)`에서 `"weights" in changes`로 비율 생략과 `weights=None` 명시를 구별할 수 있다(김영광 코드 대조 완료).
- 삭제는 물리적으로 지우지 않고 `deleted=True`, 되살리기는 `deleted=False`로 바꾼다. 수정·삭제·되살리기 전후의 사본을 `Store.record`로 남긴다.

### 1-2. 자료 항목

| 항목 | 형식 | 상태 |
|---|---|---|
| `deleted` | 지출 dict 안의 `true`/`false`. 새 지출은 `false`; 옛 자료에서 키가 없으면 `false`로 판단 | **확정(이승경, 11/16)** |
| `history` | `EMPTY["history"] = []`. 한 건은 `{"at": "YYYY-MM-DD HH:MM:SS", "action": "작업 종류 문자열", "eid": 3, "before": {…} 또는 null, "after": {…} 또는 null}`. `before`·`after`는 변경 시점의 사본 | **확정(이승경, 11/16; 김영광 확인)** |

- `Store.record`는 위 형식으로 `history`에 한 건을 추가하며 반환값은 `None`이다. `at`은 기록을 작성한 로컬 시각이다. `before`/`after`를 원본 객체로 참조하지 않고 복사해 이후 수정으로 과거 이력이 달라지지 않도록 한다.
- `action` 표준값은 `add`, `edit`, `delete`, `restore`, `undo`, `exclude`이다. **기능 4의 `exclude_member`가 `exclude`를 사용하는 것을 김영광이 확인했다.** 또한 다른 기존 호출자가 쓰는 작업명은 스켈레톤 확인 없이 제한하지 않는다.
- **구현 담당:** 기능 1 이승경이 `moim/common/store.py`의 `EMPTY["history"]`와 `Store.record`를 추가한다(현재 스켈레톤에는 아직 없음). 팀 협업 규칙에 따라 담당 주석을 붙이고, 다른 사람의 항목은 변경하지 않는다.

### 1-3. 결정 및 타 기능 확인 사항

| 번호 | 결정 사항 | 상태 | 확인할 사람 |
|---|---|---|---|
| 1 | `validate`에서 확정 기간(`is_locked`)을 검사한다. 가져오기 미리 보기와 실제 등록이 같은 잠금 판단을 사용한다 | **확정(이승경, 11/16; 김영광 확인; 류강현, 11/18: 기능 6 미리 보기 연동 확인)** | 김영광 확인 완료 / 류강현 확인 완료 |
| 2 | `members` 변경 시 기존 비율 키가 맞지 않으면 거부한다. 명시적 `weights=None`이면 균등 분배한다. `edit_expense(store, eid, **changes)`의 `"weights" in changes`로 명시 여부 구별 | **확정(이승경, 11/16; 김영광 확인·스켈레톤 대조)** | 김영광 확인 완료 |
| 3 | `history.action` 기본 목록을 `add/edit/delete/restore/undo/exclude`로 정한다. 각 기능은 변경 전후 사본을 기록한다 | **확정(이승경, 11/16; 김영광 확인)** | 김영광(`exclude_member`) 확인 완료 |
| 4 | `add_expense`의 중복 의심 경고를 `list[str]`로 제안한다. 스켈레톤의 `add_expense` docstring은 반환값을 `(지출, 경고 목록)`으로 명시한다. `ledger.duplicates`의 지출 번호 목록을 경고 문구로 바꾸며, 중복 의심만으로 등록을 막지 않는다 | **확정(이승경, 11/16; 류강현, 11/18: duplicates 연동 확인)** — 반환 구조는 스켈레톤 대조 완료 | 류강현(`duplicates`) 확인 완료 |

> **스켈레톤 대조 결과(김영광 검토):** `moim/features/expenses.py`의 `edit_expense(store, eid, **changes)`는 `"weights" in changes`로 비율의 생략과 명시적 `None`을 구별할 수 있다. `add_expense`의 docstring은 반환값을 `(지출, 경고 목록)`으로 정의한다. 함수 이름·인자는 `규약.md` 8절에 따라 유지한다.

### 3-3. 기능 함수의 반환 형식 (명령·통합 시나리오 테스트가 씀) — 확정(류훈태, 11/22)

- `month_over_month(store, month)` → `(이번 달, 지난달, 증감, 증감률 %)`. 증감률은 정수이고 0 에서 먼 쪽으로 사사오입한다(8 → 9 는 +13). 지난달이 0원이면 증감률은 `None`
- `weekday_totals(store, start, end)` → `{'월': 합계, ..., '일': 합계}`. 7개 요일을 월~일 순서로 모두 담는다(지출 없는 요일은 0)
- `week_totals(store, start, end)` → `{'그 주 월요일 YYYY-MM-DD': 합계}`. 지출 없는 주도 넣는다. 시작이 끝보다 늦으면 `{}`
- `top_expenses(store, start, end, n=5)` → 지출 dict 목록(원본). 금액 큰 순, 같으면 날짜·번호 순. `n` 이 0 이하이면 `[]`
- `biggest_day(store, start, end)` → `(날짜 'YYYY-MM-DD', 그날 합계)`. 합계가 같으면 빠른 날짜. 지출이 없으면 `None`
- `search(store, start=None, end=None, person=None, min_amount=None, max_amount=None, word=None)` → 지출 dict 목록(날짜 → 번호 순). 조건을 여러 개 주면 모두 만족하는 것만 찾는다
  - `person`: 낸 사람이거나 참여자인 지출. 금액은 양 끝을 포함하고 `"5,000"` 같은 글자도 받는다. `word`: 메모에 들어 있는 낱말. 금액 범위가 모순이면 `[]`
- 모든 기간 함수는 삭제된 지출을 뺀다(`expenses_in` 사용). 합계는 `queries.period_total` 과 같은 값이다(6-2 4번)
- `month_report(store, month)` → 문자열. 제목, 합계(건수), 전월 대비, `[분류별]`(표와 막대그래프), `[사람별 낸 돈]`, `[요일별]`, `[큰 지출 5건]`, 가장 많이 쓴 날 순서. 지출이 없는 달은 제목과 `이 달에는 지출이 없습니다.` 만 돌려준다. 달 글자가 잘못되면 ValueError
- `save_report(text, path)` → 저장한 경로. `.txt` 가 아니면 ValueError, 폴더가 없으면 FileNotFoundError. 끝에 줄바꿈이 없으면 한 줄 붙여 저장한다
