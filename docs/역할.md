## 2. 담당자가 채울 공통 함수

공통 함수는 다른 기능도 같이 쓴다. 아래 "쓰는 기능" 담당자는 그 함수가 병합될 때까지 기다리거나, 임시 값으로 테스트한다.
공통 모듈(`moim/common`)을 바꾸는 PR은 무엇을 왜 바꿨는지 설명에 적는다(규약.md 8절).

| 담당 | 공통 함수 | 쓰는 기능 |
|---|---|---|
| 이승경(1) | `ledger.validate` — 지출 한 건 검사 | 6 |
| | `ledger.insert` — 검사 후 저장 | 4, 5, 6 |
| 백지윤(2) | `queries.category_of` — 지출의 분류 이름 | 3, 5, 6 |
| | `queries.category_totals` — 분류별 건수·금액 | 3, 5 |
| 류훈태(3) | `queries.expenses_in` — 기간 안의 지출 목록 | 전원 |
| | `queries.person_paid` — 사람별 낸 돈 | 4 |
| | `textfmt.table`, `textfmt.bar_chart` — 글자 표, 막대그래프 | 1, 4, 5 의 명령 |
| 김영광(4) | `money.split` 의 비율 분배 부분 | 5 |
| | `queries.expense_shares`, `queries.member_shares` — 지출별·사람별 부담액 | 5 |
| | `queries.is_locked` — 확정 기간인가 | 1, 6 |
| 이정배(5) | `queries.is_member_active` — 그날 회원인가 | 1 |
| | `queries.active_members` — 그날 회원 목록 | 5, 6 |
| | `dates.months_between` — 두 달 사이의 달 목록 | 3 |
| 류강현(6) | `ledger.duplicates` — 같은 날·사람·금액 지출 찾기 | 1 |
| | `dates.month_key` — 날짜의 달 이름 | 3 |
| | `queries.period_total` — 기간 합계 | 3, 5 |
| | `csvio.detect_encoding`, `csvio.read_csv_rows` — 인코딩 판별, CSV 읽기 | 5 |

여러 기능이 기다리는 함수(`expenses_in`, `ledger.insert`, `category_of`, `period_total`, `is_member_active`, `is_locked`)는 먼저 만들어 병합한다.

## 3. 담당자가 추가할 자료 항목

`moim/common/store.py` 의 `EMPTY` 에 추가만 한다. 다른 사람의 항목은 바꾸지 않는다.

| 담당 | 자료 항목 |
|---|---|
| 이승경(1) | 지출의 삭제 표시(`deleted`), 수정·삭제 이력(`history`, `Store.record`) |
| 백지윤(2) | 직접 정한 분류의 고정 표시(`category_fixed`) |
| 김영광(4) | 사람별 비율(`weights`), 송금 기록(`transfers`), 확정 기간(`locks`), 반복 지출(`recurring`) |
| 이정배(5) | 회비 입금(`payments`) |

`store.py` 는 여러 사람이 같이 고치므로 충돌이 나기 쉽다. 작업 전에 main 을 받고, 항목 추가만 담은 작은 PR로 먼저 병합한다.

## 4. 저장소 관리

| 역할 | 맡은 사람 | 하는 일 |
|---|---|---|
| 관리자 | dudrhkd(김영광), seolbinga(이승경) | 팀원 초대·권한, 저장소 설정 |
| PR 승인 | 관리자 or 공통 함수 기능 담당자 | 자기 PR은 자기가 승인할 수 없다. 공통 함수 PR은 그 함수를 쓰는 기능 담당자가 보는 것이 좋다 |

- 저장소 규칙(main 보호, 병합 방식)은 관리자도 끄거나 바꾸지 않는다. 작업 방법은 `docs/작업방식.md` 를 따른다.
