# 작업 방식 (Git · 병합 요청)

저장소: https://github.com/like-people/HI_PJ

## 1. main 규칙
- main 에는 직접 push 할 수 없다. 모든 변경은 브랜치를 만들어 병합 요청(PR)으로 넣는다.
- 병합하려면 두 가지가 모두 필요하다.
  - 다른 팀원 1명 이상의 승인(Approve). 자기 PR은 자기가 승인할 수 없다.
  - 자동 검사 `check` 통과(문법 검사, 기능끼리 import 검사, 팀 테스트).
- 강제 push(force push)와 main 삭제는 막혀 있다.
- 관리자를 포함해 누구도 이 규칙을 건너뛸 수 없다. 규칙은 끄거나 바꾸지 않는다.
- 병합 방식은 "Create a merge commit" 하나만 쓴다(스쿼시·리베이스 병합은 꺼져 있다).
- 관리자: dudrhkd(팀장), seolbinga.

## 2. 처음 한 번
```
git clone https://github.com/like-people/HI_PJ.git
cd HI_PJ
git config user.name "내 GitHub 아이디"
git config user.email "내 GitHub 계정에 등록·인증된 이메일"
```
- 커밋의 기고자는 이메일로 정해진다. 계정에 등록되지 않은 이메일이면 기고가 내 계정으로 잡히지 않는다.
- 이메일 확인: https://github.com/settings/emails

## 3. 작업 순서
1. 최신 main 받기
   ```
   git checkout main
   git pull
   ```
2. 브랜치 만들기 — 이름은 `종류/내용` (예: `feat/settle-report`, `fix/split-remainder`, `docs/readme-usage`)
   ```
   git checkout -b feat/settle-report
   ```
3. 작업한 뒤 올리기 전에 직접 검사하기
   ```
   python -m compileall -q moim tools
   python tools/check_imports.py
   python -m unittest discover -s tests
   ```
4. 커밋하고 브랜치 올리기
   ```
   git add 바꾼파일
   git commit -m "feat: 정산 보고서 출력 추가"
   git push -u origin feat/settle-report
   ```
5. GitHub에서 병합 요청 만들기 — push 결과에 나오는 링크를 열고 **Create pull request**.
   설명에는 무엇을 왜 바꿨는지 적는다. `moim/common` 을 바꿨으면 반드시 적는다(규약.md 8절).
6. 팀원에게 승인 부탁 — 승인하는 사람은 **Files changed → Review changes → Approve → Submit review**.
7. `check` 가 초록색이고 승인이 있으면 **Merge pull request → Confirm merge**.
8. 병합한 뒤 정리
   ```
   git checkout main
   git pull
   git branch -d feat/settle-report
   ```

## 4. 커밋 메시지
- `종류: 한 줄 요약` 형식으로 쓴다.
- 종류: `feat`(기능 추가) · `fix`(오류 수정) · `test`(테스트) · `docs`(문서) · `refactor`(동작 그대로 구조 정리) · `chore`(설정·도구)

## 5. 자주 생기는 일
- **`push declined due to repository rule violations`**: main 에 직접 push 했다. 브랜치를 만들어 다시 올린다.
  ```
  git checkout -b fix/내용
  git push -u origin fix/내용
  ```
  그 뒤 main 을 원래대로 돌리려면 팀장에게 묻는다.
- **`check` 실패**: PR 화면의 `check` 옆 **Details** 에서 어느 단계가 실패했는지 보고, 고친 뒤 같은 브랜치에 다시 push 한다. PR에 자동으로 반영된다.
- **충돌(conflict)**: 내 브랜치에서 main 을 받아 합친 뒤 충돌 난 파일을 고친다.
  ```
  git checkout 내브랜치
  git pull origin main
  (충돌 파일 수정)
  git add 수정한파일
  git commit
  git push
  ```
- **`Everything up-to-date`**: 올릴 새 커밋이 없다. `git add` 만 하고 `git commit` 을 안 했는지 확인한다.

## 6. 하지 않는 것
- main 에서 바로 작업하지 않는다.
- 남의 브랜치에 말없이 push 하지 않는다.
- 승인 없이 병합하려고 규칙을 바꾸지 않는다.
- 비밀번호·토큰·개인 자료 파일(`config.json` 등)을 커밋하지 않는다.
