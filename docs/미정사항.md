| 번호 | 정할 것 | 정하는 사람 | 기한 | 반영할 곳 | 상태 |

| 1 | 팀 공동 작업 6개의 담당자 | 팀 전원 | 11/11 착수 때 정했어야 함 → 가장 급함 | `docs/역할.md` 2절 | 정함 |

## 1. 팀 공동 작업 담당자

공고문: "팀 공동 작업은 6명이 나누어 맡고, 누가 무엇을 했는지 저장소 이력에 남긴다." 기능과 같은 6명이 기능 하나와 공동 작업 하나를 맡는다.

| 공동 작업 | 난이도 | 담당 |
|---|---|---|
| 통합 실행 | 보통 | 이승경 |
| 설정 파일 | 쉬움~보통 | 백지윤 |
| 로그 | 쉬움 | 류강현 |
| 자료 파일 손상 대응 | 보통 | 이정배 |
| 사용 설명서 | 코드는 쉬움, 마감 직전에 몰림 | 류훈태 |
| 통합 시나리오 테스트 | 어려움 | 김영광 |

나눌 때 참고할 점
- 기능 4(정산)와 기능 5(예산·회비, 은행 가져오기)는 무거운 편이다. 가벼운 공동 작업을 주면 균형이 맞는다.
- 설정 파일의 `load_members_file` 은 기능 1 파일 안에 있다. 기능 1 담당이 맡으면 따로 승인을 받지 않아도 된다.
- 자료 파일 손상 대응은 기능 6의 백업·복원과 비슷하다.
- 통합 시나리오 테스트는 6개 기능이 다 돌아야 시작할 수 있다. 자기 기능을 일찍 끝낼 수 있는 사람이 맡는다.

## 2. 설정 파일 항목 이름

`config.example.json` 의 초안이다. `tests/helpers.py` 도 이미 `budget`, `dues`, `warn_ratio`, `rules` 이름을 쓰므로 그대로 확정하는 것이 쉽다.

| 항목 | 뜻 | 쓰는 기능 |
|---|---|---|
| `group` | 모임 이름 | 통합 실행 |
| `data` | 자료 파일 위치 | 통합 실행 |
| `members_file` | 명부 파일 위치 | 설정 파일(`member load`) |
| `rules` | 분류 규칙 파일 | 기능 2 |
| `backup_dir`, `log_dir` | 백업·로그 폴더 | 자료 파일 손상 대응, 로그 |
| `treasurer` | 총무 | 기능 5(은행 거래내역 가져오기) |
| `budget.monthly`, `budget.by_category` | 월 예산, 분류별 예산 | 기능 5 |
| `dues.monthly` | 1인당 월 회비 | 기능 5 |
| `warn_ratio` | 경보 비율(0.8) | 기능 5 |

정할 것: 이 이름으로 확정하는가, 바꿀 항목이 있는가.

## 4. 협업 규칙 합의문 (11/18 제안발표)

`docs/작업방식.md` 를 바탕으로 공고문의 개발 규칙을 합의문으로 정리한다. 들어가야 할 것
- 한 PR에 한 가지 변경, 300줄 이하, 기능을 추가하면 테스트를 같은 PR에 넣기
- 검토 의견에는 확인한 내용(실행한 명령과 결과, 규약 값과 대조한 줄)을 적는다. "확인했습니다"만 적은 검토는 검토 건수에 넣지 않는다
- 1인당 다른 사람의 PR 5건 이상 검토, 공통 모듈 PR 2건 이상
- 다른 사람의 기능 파일은 그 담당자 승인 없이 고치지 않는다. 충돌을 풀 때 다른 사람의 변경을 지우지 않는다
- 잘못 병합한 것은 `git revert` 로 되돌린다(force push 금지)

정할 것: 위 내용 외에 팀 자체 규칙(검토 요청 방법, 응답 기한, 연락 방법 등)
